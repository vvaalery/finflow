# FinFlow — запуск

## Один командный запуск
```bash
./start.sh
```

После запуска:
- frontend: http://localhost:5173
- backend GraphQL/GraphiQL: https://localhost:8443/graphiql
- GraphQL endpoint: https://localhost:8443/graphql
- health: https://localhost:8443/actuator/health

Самоподписанный TLS-сертификат создаётся контейнером автоматически.

## Demo admin
- email: admin@finflow.local
- password: Admin123!

Пароль при старте сохраняется в PostgreSQL только как BCrypt-хеш.

## Backup / restore
```bash
./scripts/backup.sh
./scripts/restore.sh ./backups/finance_db_YYYYMMDD_HHMMSS.dump
```

## Benchmark
```bash
./scripts/benchmark.sh
```

## Восстановление компании и счетов
При старте backend проверяет наличие демонстрационной компании `Creative Pulse Design Studio` у `admin@finflow.local`. Если профиль отсутствует, он создаётся вместе с двумя счетами; если история операций пуста, добавляется небольшой набор исторических операций для проверки прогноза. Существующие счета и операции не перезаписываются.

Если нужно выполнить SQL вручную на уже запущенном контейнере:
```bash
./scripts/restore-company-data.sh
```
Скрипт `scripts/restore-company-data.sql` идемпотентен и в конце выводит контрольную выборку компании и связанных счетов.

## Прогнозирование
Во вкладке «Финансовый прогноз» по умолчанию выбрана ансамблевая модель градиентного бустинга. Доступны базовый, оптимистичный и консервативный сценарии, а также альтернативные методы сравнения. Прогноз строится по историческим операциям выбранной компании; помесячные значения возвращаются API и отображаются на графике.

## Доступ к разделам
Навигация строится на основе роли авторизованного пользователя. Разделы без прав не отображаются. Backend дополнительно защищает операции через Spring Security и `@PreAuthorize`; скрытие элемента интерфейса не является единственным уровнем контроля.
